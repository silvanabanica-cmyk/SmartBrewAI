## 3. Unresolved questions and assumptions

The system description leaves some implementation details open. The following questions should be resolved or explicitly recorded as unspecified.

1. Offline payments: What does “offline card processing/cashless storage” mean operationally? Which payment methods can actually be used without a network connection, and what happens when a payment cannot be authorized?
2. Ingredient thresholds: Who configures the minimum ingredient thresholds, and are they fixed or configurable?
3. Recommendations: How are recommendation scores calculated, and how should the system behave if weather data is unavailable?
4. Mood detection: Is camera-based mood detection always enabled, or can a user decline it? The description specifies image handling but does not define consent or opt-out behavior.
5. Optional LLM assistant: Is the assistant enabled in every deployment, and what should happen when it cannot interpret a request?
6. Performance: What response-time targets, if any, are required for recommendations, menu interactions and payment processing?
7. Data retention: How long should transaction records, event logs and user profiles be retained?
8. Payment security: Which payment processor integrations and security standards are required?
9. Waste-bin monitoring: What happens if a capacity sensor fails or reports an invalid reading?
10. Receipt delivery: What should happen if an email cannot be sent or a QR receipt cannot be generated?
